# Nexus Control 功能介绍与操作指南

Nexus Control 是运行在 Windows 本机上的本地终端与服务编排应用。它用 Electron 承载窗口和终端界面，用 React 管理页面状态，用 xterm.js 显示终端，用项目内的 Node.js 后端连接 WSL、Windows PowerShell、PowerShell 7 和 CMD。

应用面向单机管理场景：服务、终端、指令、编排、定时任务和日志都保存在本机，不需要云端账号，也不会把后端暴露到局域网。

> 截图说明：本文截图来自当前版本的页面演示数据。截图中的服务名、路径和数量只是为了展示控件；实际内容以你本机的 `backend/servers.json` 和运行环境为准。

## 1. 运行方式

### 1.1 开发版 Electron（推荐）

在 PowerShell 中进入项目目录后执行：

```powershell
cd E:\airtest\terminal_maneger
npm.cmd run dev
```

该命令会启动 Vite、Electron 和由 Electron 管理的本地 WSL 后端。应用窗口打开后，右上角应显示“本地后端 · 已连接”。

点击窗口关闭按钮时会显示关闭确认：可以关闭服务并退出客户端，也可以最小化到系统托盘。勾选“下次不再提醒”后，应用会记住本次选择；之后可在设置页重新开启提醒或修改默认动作。

### 1.2 已构建的 Electron

先构建前端，再启动 Electron：

```powershell
cd E:\airtest\terminal_maneger
npm.cmd run build
npm.cmd start
```

`npm.cmd start` 使用 `dist` 目录中的构建结果。它仍会由 Electron 尝试启动项目内的后端。

### 1.3 浏览器预览

```powershell
cd E:\airtest\terminal_maneger
npm.cmd run web
```

浏览器预览适合查看 UI。它不会替代 Electron 的窗口生命周期管理；如果后端不可用，页面会保留离线预览终端。需要真实 PTY、tmux 重连和应用退出时调度停止时，请使用 Electron。

如需手动同时运行后端和网页：

```powershell
npm.cmd run dev:full
```

### 1.4 `package.json` 找不到的原因

`npm` 必须在项目目录执行。如果提示：

```text
C:\Windows\system32\package.json: ENOENT
```

说明当前 PowerShell 工作目录是 `C:\Windows\System32`，不是项目目录。先执行：

```powershell
cd E:\airtest\terminal_maneger
npm.cmd run dev
```

不要通过双击 `npm` 文件启动应用；请在项目目录使用上面的脚本。

## 2. 架构与数据位置

### 2.1 进程关系

```text
Electron 主进程
  ├─ React / xterm.js 渲染窗口
  └─ 本地 backend/server.cjs
       ├─ WSL Ubuntu + tmux PTY
       ├─ Windows ConPTY（PowerShell / pwsh / CMD）
       ├─ 服务编排与定时调度
       └─ 项目日志文件
```

- 后端只监听 `127.0.0.1:4317`，不会监听公网或局域网地址。
- Vite 开发网页默认使用 `127.0.0.1:5173`。
- Electron 最小化时不会停止后端和定时任务。
- 正常退出 Electron 时，后端调度器停止；WSL 中已有的 tmux 服务会话保留。
- 选择“最小化到托盘”时客户端窗口隐藏，但后端、定时任务和服务继续运行。
- 选择“关闭服务并关闭客户端”时会向各终端发送配置的停止命令（未配置时发送 Ctrl+C），然后停止后端调度器；tmux 会话本身保留。
- 应用不会自动修改 Windows Terminal、注册表、Windows 服务或 WSL 配置。

### 2.2 配置文件

正式配置文件固定为：

```text
E:\airtest\terminal_maneger\backend\servers.json
```

设置页只显示这个路径，不能在应用内切换。配置文件使用版本化 JSON，包含：

- `groups`：服务分组和终端信息。
- `terminalWorkspaces`：终端工作区定义；每组可有 0–4 个终端，用于终端页的分屏视图，不参与服务分组、批量指令或服务编排。三成员工作区会保存独立的三列比例，四成员工作区会保存独立的田字分屏比例。
- `servers`：终端类型、工作目录、端口、tmux 会话、启动/停止命令和就绪条件。
- `commands`：指令库。
- `workflows`：服务编排步骤。
- `schedules`：定时任务。
- `settings`：后端保留设置，例如日志保留策略。

应用保存配置时采用临时文件替换，减少中断造成半截 JSON 的风险。旧版扁平服务配置会在保存时转换为分组结构。

### 2.3 日志目录

源码运行时日志在：

```text
E:\airtest\terminal_maneger\backend\logs
```

每个终端一个文件，例如 `server-local1.log`。打包版使用应用目录下的 `data\logs`。日志页可以直接打开目录或单个日志文件。

## 4. 第一次使用

### 4.1 检查 WSL

在 PowerShell 执行：

```powershell
wsl.exe -l -v
wsl.exe -d Ubuntu-18.04 -- uname -a
```

只要能列出发行版并执行 `uname`，就可以在 Nexus 中创建 WSL 终端。应用会读取 Windows Terminal 的默认 WSL 发行版；如果没有可用发行版，WSL 终端会显示不可用状态，但 Windows Shell 仍可以使用。

### 4.2 检查 tmux

WSL 终端可以在没有 tmux 时作为普通 bash 使用，但要实现服务会话持久化和应用重启后重连，需要 tmux。可以在“设置”页查看状态。

![设置页面](assets/10-settings.png)

点击“一键安装 tmux”后，应用会再次弹窗确认，并在检测到的 Ubuntu 中以 root 执行：

```bash
apt-get update
apt-get install -y tmux
```

安装只在用户确认后发生，不修改 Windows Terminal、注册表或其他 WSL 发行版。

## 5. 新建终端

### 5.1 打开新建窗口

在“服务管理”页点击“新建终端”，或在终端页“全部终端”标题右侧点击加号。

![新建 WSL 终端](assets/04-new-terminal-wsl.png)

### 5.2 选择终端类型

支持以下类型：

- **WSL Ubuntu**：通过 `wsl.exe` 启动 bash；如果启用 tmux，会绑定 `nexus-<终端 id>` 会话。
- **Windows PowerShell**：直接在 Windows 本机运行 `powershell.exe`，不经过 Ubuntu。
- **PowerShell 7**：本机安装 `pwsh.exe` 后才会显示为可用。
- **命令提示符（CMD）**：直接在 Windows 本机运行 `cmd.exe`。

![新建 PowerShell 终端](assets/05-new-terminal-powershell.png)

### 5.3 工作目录

- WSL 终端目录留空时使用 `/root`。
- Windows PowerShell、PowerShell 7 和 CMD 目录留空时使用当前 Windows 用户目录。
- 可以手动输入路径，也可以点击文件夹图标选择目录。
- WSL 路径使用 Linux 格式，例如 `/srv/minecraft/main`；Windows Shell 使用 Windows 路径。

填写名称和分组后保存。应用会把新终端写入 `servers.json`，并刷新服务列表。

## 6. 服务管理

![服务管理页面](assets/02-service-management.png)

### 6.1 分组与勾选

服务管理页以分组显示终端：

1. 点击分组复选框，选中或取消该分组的所有终端。
2. 点击单个终端左侧复选框，只切换该终端。
3. 点击分组箭头可以折叠或展开服务列表。
4. 选择状态会同步到指令库页面，用于批量广播命令。

### 6.2 打开、停止和删除

- 点击终端名称或终端图标，进入对应的真实终端。
- 正在运行的服务显示停止按钮；停止动作优先使用服务的 `stopCommand`，没有配置时发送 Ctrl+C。
- “更多操作”菜单包含打开终端、停止服务和删除终端。
- 删除终端会停止对应 PTY/tmux 会话，并尝试释放该终端配置的端口；确认端口不再占用后才会从 JSON 中删除。
- 删除后服务管理和终端列表会刷新；被删除终端关联的定时任务会被禁用或移除该目标。

### 6.3 为什么没有“启动已选”

服务管理页不提供通用的“启动已选”或“重启已选”按钮，因为不同服务的启动脚本、目录、等待条件和依赖顺序可能完全不同。

服务启动统一放在“服务编排”中配置：在步骤里指定服务动作、启动命令、等待日志、超时和重试，然后点击“立即运行”。这样不会把 `./mysrv.py start` 之类的命令硬编码到应用里。

## 7. 真实终端

![终端页面](assets/03-terminal.png)

真实 Electron 后端连接成功后，右侧是 xterm.js PTY 画布，不是静态文本列表。WSL tmux 会话使用 `nexus-<serverId>` 命名，切换页面或重启 Electron 后可以重新接入。

### 7.1 终端工作区

“终端工作区”是终端页专用的持久化分屏组织方式，和“服务管理”里的服务分组完全独立：服务分组用于归类、勾选和批量执行，工作区只决定哪些终端一起显示。一个终端可以加入多个工作区。

1. 点击“终端工作区”标题右侧的加号可新建空工作区；输入名称后可立即保存，成员可以稍后再添加。
2. 在工作区三点菜单选择“编辑成员与名称”，可改名并勾选 0–4 个终端；第 5 个终端会被禁用。
3. 在“全部终端”里点击任意终端，会将当前视图替换为该终端单屏。终端右侧三点菜单可将它加入任意未包含它且尚未满员的工作区。
4. 点击工作区会将当前视图替换为该工作区的分屏；成员按保存顺序显示。1 / 2 个成员维持横向分屏；3 个成员显示为横向三屏；4 个成员显示为田字形 2×2 PTY。
5. 三屏时可拖动两条竖线调整三列宽度；四屏时可拖动中间竖线调整左右终端宽度，拖动中间横线调整上下终端高度。双击任一分割线恢复均分，比例会按工作区保存，切换工作区或重启应用后仍会保留。
6. 窄窗口会自动切为纵向单列并隐藏分割线，窗口恢复到足够宽时恢复对应分屏布局。
7. 点击任意终端格可切换当前焦点。每格都有独立的搜索、滚动条、连接状态、复制、粘贴和清屏；侧边指令只作用于当前焦点格。
8. 删除工作区只删除工作区定义，不会停止服务、删除终端配置、断开其他工作区或终止 tmux 会话。删除终端配置时，应用会自动清理所有工作区中的对应成员引用；其余成员继续显示。

工作区定义保存于 `servers.json` 的 `terminalWorkspaces` 字段；当前选中的工作区不保存。重新启动应用后，终端页默认打开第一个可用终端的单屏视图。

终端支持：

- bash、PowerShell、PowerShell 7 和 CMD 的原生输入处理。
- Tab 自动补全。
- 上下方向键调用 shell 历史。
- Ctrl+C 中断当前命令。
- ANSI 颜色、光标和窗口 resize。
- 终端断线后自动重连；新的连接会接管旧连接，避免两个页面互相闪烁。
- 重新打开应用时终端以初始化状态开始，不回放上一次的输出；历史内容在“日志检索”中查看。
- 终端滚动和最多 10000 行 xterm.js scrollback（仅限本次连接产生的输出）。
- 工具栏搜索当前终端输出，并用上下箭头跳转匹配项。
- 鼠标拖选文本后右键复制，或按 Ctrl+Shift+C 复制选中内容。

后端暂时不可用时，终端会切换到本地预览模式。预览模式提供基本的 `ls`、`pwd`、`echo`、`clear`、Tab 和历史演示，但不会执行真实服务命令；恢复后端后会自动重连真实 PTY。

### 7.2 当前终端指令库

终端左侧列表下方有“当前终端指令库”。点击“选择指令”可以搜索并使用命令：

- 直接执行型指令会发送命令并附加回车。
- 粘贴型指令只写入终端，不发送回车，光标停在末尾，适合手动补参数。
- 终端工具栏上的搜索只搜索当前 xterm 画布；历史日志搜索请使用“日志检索”页。

## 8. 指令库

![指令库页面](assets/06-command-library.png)

### 8.1 选择目标终端

指令库顶部的“指令目标”区域支持：

- 勾选整个分组。
- 勾选分组中的部分终端。
- 直接勾选单个终端。
- 清空全部选择。

直接执行型命令可以广播到多个终端；粘贴型命令必须只选择一个终端，因为每个终端需要用户自行补参数。

### 8.2 新建和编辑指令

点击“新建指令”打开编辑窗口：

![指令编辑窗口](assets/06-command-editor.png)

需要填写：

- 指令名称。
- 终端指令内容。
- 发送方式：**直接执行**或**粘贴到终端**。
- 说明、适用范围和颜色标识。

点击卡片右上角的三个点，可以编辑、复制、切换发送方式或删除：

![指令操作菜单](assets/07-command-menu.png)

编辑保存后，卡片和 `servers.json` 会立即刷新。删除后不会因为后端轮询而重新出现；如果其他窗口仍显示旧内容，点击顶部刷新按钮重新加载配置。

### 8.3 执行与粘贴

- 选中一个或多个目标后，点击“执行”发送直接执行型命令。
- 粘贴型命令按钮显示“粘贴”，点击后会跳转到目标终端，并把内容写入输入区，不自动回车。
- 如果粘贴型命令选择了多个终端，应用会提示先只保留一个目标。

### 8.4 导入和导出

点击“导出命令库”会生成版本化 JSON 文件。导出内容只包含名称、命令、说明、发送方式、适用范围和颜色，不包含本机终端、分组、路径、端口或执行次数。

点击“导入命令库”选择 JSON 文件：

- 最大文件大小为 5 MB，最多导入 5000 条。
- 导入采用合并模式，完全相同的指令会跳过。
- 新导入指令的执行次数从 0 开始。
- 导入后会刷新当前页面和本地配置。

## 9. 服务编排

![服务编排页面](assets/07-orchestration.png)

服务编排是“一键开服”的配置入口。根步骤按顺序执行，并行组中的分支同时开始；并行不是让同一个终端同时执行多条命令，而是把不同分支分别下发给不同终端。

### 9.1 步骤类型

每个步骤都可以指定名称、超时、重试次数和失败策略：

- **发送命令**：选择一个目标终端，再选择指令库命令或直接输入临时命令。
- **服务动作**：对指定终端执行启动、停止或重启。启动命令来自该终端的配置或后端服务动作逻辑。
- **固定等待**：等待指定毫秒数。
- **等待日志**：选择终端并等待日志出现关键字。
- **并行任务组**：添加多个分支，每个分支单独选择一个目标终端。

### 9.2 并行分支约束

![并行编排编辑器](assets/07-orchestration.png)

并行组的每个分支必须选择目标终端；应用会提示重复目标。后端也会校验同一并行组中不能有两个分支指向同一个终端，确保每个并行任务由一个终端执行。

### 9.3 等待、超时和重试

- 固定等待适合等待进程初始化或端口准备。
- 等待日志适合等待服务输出 `Done`、`Listening` 等完成标志。
- 超时单位是毫秒；超时后按重试次数重新执行该步骤。
- 失败后可以选择“停止”或“继续”。继续会记录错误并进入下一步。
- 点击“立即运行”后，页面显示运行状态和每个步骤的结果；后端通过 `GET /api/runs/:runId` 提供运行详情。

### 9.4 一键开服建议流程

1. 新建一个编排，例如“启动联机环境”。
2. 添加服务动作步骤，分别选择需要启动的终端。
3. 如果服务依赖顺序，使用顺序步骤；可以在两个无依赖服务之间插入并行组。
4. 为每个启动步骤填写超时和重试次数。
5. 在启动步骤后添加固定等待或等待日志关键字。
6. 保存后点击“立即运行”，根据运行状态和日志检查结果。

不要把通用启动命令写死在文档或应用按钮里；请按你自己的服务填写每个终端的实际命令和目录。

## 10. 定时任务

![定时任务](assets/08-schedules.png)

定时任务位于服务编排页下方，可选择两类执行内容：

- **编排**：运行已保存的服务编排。
- **指令**：选择指令库命令，或输入临时命令，并勾选目标终端。

执行周期当前提供：

- **指定日期时间**：一次性执行，到达本机日期和时间后运行。
- **固定间隔**：按照间隔运行，可选择“执行一次”或“循环执行”。

固定间隔同时显示毫秒和时、分、秒输入框，修改任一项都会同步换算。后端最小间隔为 1000 毫秒。

旧版 JSON 中的 `cron` 字段仍可被后端兼容读取；当前界面新建任务使用日期时间或固定间隔，不再把 Cron 表达式作为主要设置入口。

调度器在 WSL 后端进程中运行：

- 窗口最小化后仍继续调度。
- 正常退出 Electron 后停止调度器。
- 不使用系统 Cron，也不创建 Windows 任务计划。
- 退出应用不会删除已有 tmux 服务会话。

## 11. 日志检索

![日志检索页面](assets/09-logs.png)

Nexus 会把终端输出保存到按终端划分的日志文件中。执行服务启动动作时，会清空该服务上一次启动产生的日志；之后 PTY/tmux 输出实时追加到对应文件。

### 11.1 搜索

日志页支持：

- 按终端筛选。
- 关键字搜索命令、报错、玩家名称或任意输出文本。
- 按 Info、Warning、Error 级别筛选。
- 按终端分组显示日志，不强制把所有终端混成一张行表。
- 点击文件图标打开某个终端的完整日志文件。
- 点击跳转图标打开对应终端。

### 11.2 搜索结果和完整上下文

搜索栏右侧的按钮可以在两种模式间切换：

- **仅显示结果**：只显示包含关键词的日志终端和行。
- **显示完整日志**：显示完整日志，并高亮匹配关键词；顶部会额外显示匹配行数量。

这样既能快速定位错误，也能查看错误前后的上下文。

## 12. 设置

设置页包括：

- **界面语言**：中文或 English，修改立即生效。
- **界面主题**：深色主题使用绿色强调色；浅色主题使用蓝色 `#339CFF` 强调色。
- **WSL 依赖**：查看 WSL 和 tmux 状态；只有点击并确认后才会一键安装 tmux。
- **本地配置**：显示固定配置路径 `backend/servers.json`。
- **运行说明**：查看离线预览、日志和退出行为。

### 12.1 关闭客户端设置

设置页的“关闭客户端”区域包含“下次不再提醒”复选框和免提醒时的默认动作。默认动作可选“最小化到托盘（保留服务运行）”或“关闭服务并关闭客户端”。该设置保存在 Electron 的用户配置中，不写入 `servers.json`。

语言和主题保存在当前浏览器/Electron 本地存储；关闭行为偏好保存在 Electron 用户配置中，均不写入 `servers.json`。

## 13. Agent / MCP 接入

Nexus 提供一个使用标准输入输出通信的本地 MCP Server，供 Codex 等 Agent 读取终端和日志。它不监听额外网络端口。

### 13.1 源码开发版

先启动 Nexus Electron，再在 PowerShell 执行：

```powershell
cd E:\airtest\terminal_maneger
codex.cmd mcp add nexus-local -- node E:/airtest/terminal_maneger/mcp/server.cjs
```

对应的 `config.toml`：

```toml
[mcp_servers.nexus-local]
command = "node"
args = ["E:/airtest/terminal_maneger/mcp/server.cjs"]
```

也可以用项目脚本检查 MCP 进程：

```powershell
npm.cmd run mcp
```

### 13.2 安装版和便携版限制

当前项目尚未实现 `Nexus Control.exe --mcp` 的正式打包入口，也没有最终安装包构建配置。因此安装版/便携版暂时不能按“直接调用 exe 的 MCP 模式”接入；发布前必须补齐该入口。

### 13.3 Agent 可用工具

- `list_terminals`：列出终端、分组和日志路径。
- `read_terminal_log`：读取指定终端最近输出。
- `search_terminal_log`：跨终端搜索日志并返回上下文。
- `watch_terminal_log`：用 cursor 等待增量输出。
- `send_terminal_command`：向终端发送命令，默认只返回预览。

可以直接对 Agent 说：

```text
列出 Nexus 当前的所有终端。
```

```text
读取 server-local1 最近 200 行输出。
```

```text
搜索所有终端中包含 error 的日志，并显示前后 3 行。
```

### 13.4 允许 Agent 执行命令

MCP 默认只读。需要执行命令时，在 Codex 配置中显式加入：

```toml
[mcp_servers.nexus-local.env]
NEXUS_MCP_ALLOW_COMMANDS = "1"
```

修改后重启 Codex，并且每次调用 `send_terminal_command` 都必须传入 `confirm: true`。建议先保持只读模式，因为日志和命令内容可能包含路径、账号、玩家信息或服务数据。

## 14. HTTP / WebSocket 接口

后端只接受本机请求，主要接口如下：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | WSL、Node、tmux、终端数量和日志状态 |
| GET / PUT | `/api/config` | 读取或保存完整 JSON 配置 |
| POST | `/api/config/reload` | 从 `servers.json` 强制重新加载 |
| POST | `/api/servers/:id/action` | 对一个或多个服务执行动作 |
| DELETE | `/api/servers/:id` | 停止、释放端口并删除终端 |
| POST | `/api/commands/dispatch` | 并行向多个终端发送命令并返回逐端结果 |
| POST | `/api/workflows/:id/run` | 启动编排运行 |
| GET | `/api/runs/:runId` | 查看编排运行状态 |
| GET | `/api/logs` | 按终端、关键字和数量查询日志 |
| GET / POST / PUT | `/api/schedules` | 查询、新增和整体更新定时任务 |
| PATCH / DELETE | `/api/schedules/:id` | 修改或删除定时任务 |
| WebSocket | `/terminal/:serverId` | 发送 `input`、`resize`，接收 `output`、`status` |

批量命令会并行发送，并为每个服务返回成功、失败和错误信息；它不会把一条命令拆成同一终端中的并发任务。

## 15. 常见问题

### 修改 `servers.json` 后页面没有更新

后端会检测文件变更，但页面有本地编辑保护。保存外部修改后，点击顶部刷新按钮，或重新加载页面；如果页面仍有未保存的编辑，先完成或放弃编辑再刷新。

### 后端显示离线

确认 Electron 正在运行，并检查 `http://127.0.0.1:4317/health`。如果后端启动超时，页面会保留离线预览终端；WSL 和 Windows Shell 仍可分别按依赖状态使用。

### tmux 不可用

在设置页确认 WSL 可用后点击“一键安装 tmux”，或者在 Ubuntu 中手动安装。没有 tmux 时，普通终端仍可用，但不能保证 WSL 服务会话在应用重启后保留。

### 删除终端后端口仍被占用

删除动作会先尝试发送停止命令、结束 tmux 会话并释放配置端口，再从 JSON 删除。若端口由外部进程占用，应用会保留该终端配置并显示占用进程，避免误删配置；先在对应系统中停止外部进程后再重试。

### 启动命令应该写在哪里

写在对应终端的 `startCommand`，并在服务编排中使用“服务动作”步骤调用。不要依赖固定的 `./mysrv.py start`，因为不同服务的脚本、目录和参数不同。

### 日志在哪里

源码版在 `backend/logs`，每个终端一个 `.log` 文件。日志页可以按终端筛选、搜索、显示完整上下文，或直接打开文件。

### Windows PowerShell、CMD 可以不用 Ubuntu 吗

可以。新建终端时选择 Windows PowerShell、PowerShell 7 或 CMD，它们直接通过 Windows ConPTY 运行，不经过 WSL。PowerShell 7 需要本机已经安装 `pwsh.exe`。

### 打包版是否自动安装 tmux

当前应用不会静默安装任何系统依赖。设置页的一键安装会明确提示并等待确认；便携版、安装版都遵循同样的确认原则。

## 16. 安全与维护建议

- 不要把后端监听地址改成 `0.0.0.0`，除非你明确设计了认证和访问控制。
- 把 `backend/servers.json` 和 `backend/logs` 纳入自己的备份策略。
- 导出命令库前检查命令中是否包含密码、令牌或内部路径。
- 启用 Agent 命令执行前，先确认 MCP 配置中的 `NEXUS_MCP_ALLOW_COMMANDS`，并保留 `confirm: true`。
- 不要把日志目录提交到公共仓库；日志可能包含账号、路径、玩家名和服务输出。
- 更新应用前先退出正在运行的 Nexus 实例；tmux 服务会话可以在应用退出后继续保留。
