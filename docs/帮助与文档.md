# Nexus Control 帮助与文档

## Agent / MCP 接入

Nexus 通过本地 MCP Server 向 Codex 等 Agent 提供终端列表、历史日志、日志搜索和增量输出。MCP 使用标准输入输出通信，不额外开放网络端口。

> 安全说明：MCP 默认只读。终端日志可能包含账号、路径、玩家信息或服务数据；Agent 调用日志工具时，相关内容会发送给该 Agent 使用的模型服务。

### 正式安装版

正式安装包不能依赖源码目录中的 `mcp/server.cjs`，也不应要求用户另外安装 Node.js。安装版必须由 Nexus 可执行文件提供 MCP 模式：

```text
Nexus Control.exe --mcp
```

安装版用户按以下步骤接入：

1. 安装并启动 Nexus Control，确认左上角显示“本地后端 · 已连接”。
2. 找到 Nexus Control 的实际安装路径。默认用户级安装路径通常位于：

   ```text
   C:\Users\<用户名>\AppData\Local\Programs\Nexus Control\Nexus Control.exe
   ```

   实际路径以安装时选择的位置为准。

3. 在 PowerShell 中执行以下命令，将 `<安装路径>` 替换为实际路径：

   ```powershell
   codex.cmd mcp add nexus-local -- "<安装路径>\Nexus Control.exe" --mcp
   ```

4. 检查 MCP 状态：

   ```powershell
   codex.cmd mcp list
   ```

   正常时会看到 `nexus-local`，状态为 `enabled`。

5. 完全退出并重新打开 Codex，或者新建一个 Codex 任务，使 MCP 工具重新加载。
6. 在 Codex 中输入“列出 Nexus 当前的所有终端”验证接入。

也可以手动编辑 Codex 的 `config.toml`：

```toml
[mcp_servers.nexus-local]
command = "C:\\Users\\<用户名>\\AppData\\Local\\Programs\\Nexus Control\\Nexus Control.exe"
args = ["--mcp"]
```

便携版只需要把 `command` 改为便携版 `Nexus Control.exe` 的绝对路径。

### 源码开发版

源码版需要本机已经安装 Node.js，并使用项目中的 MCP 脚本：

```powershell
codex.cmd mcp add nexus-local -- node E:/airtest/terminal_maneger/mcp/server.cjs
```

对应的手动配置为：

```toml
[mcp_servers.nexus-local]
command = "node"
args = ["E:/airtest/terminal_maneger/mcp/server.cjs"]
```

配置完成后重启 Codex。启动 Nexus Electron 应用：

```powershell
cd E:\airtest\terminal_maneger
npm.cmd start
```

### Agent 可用工具

- `list_terminals`：列出 Nexus 中配置的终端、分组和日志路径。
- `read_terminal_log`：读取一个终端最近保存的输出。
- `search_terminal_log`：在一个或全部终端中搜索日志，并返回上下文。
- `watch_terminal_log`：使用 cursor 增量等待新输出。
- `send_terminal_command`：向终端发送命令；默认只返回预览。

可直接向 Agent 提出以下请求：

```text
列出 Nexus 当前的所有终端。
```

```text
读取 cytlocal1 最近 200 行输出。
```

```text
搜索所有终端中包含 Done 的日志，并显示前后 3 行。
```

```text
持续查看 cytlocal1 的新输出，发现 error 时告诉我。
```

### 允许 Agent 执行命令

MCP 默认禁止实际发送命令。只有明确需要时，才在 Codex 配置中启用：

```toml
[mcp_servers.nexus-local.env]
NEXUS_MCP_ALLOW_COMMANDS = "1"
```

修改后需要重启 Codex。即使开启，`send_terminal_command` 每次调用仍必须传入 `confirm: true`。

建议先保持只读模式。需要执行命令时，应在当前请求中明确目标终端、完整命令和“确认执行”，例如：

```text
在 cytlocal1 执行 ./mysrv.py status，确认执行。
```

### 常见问题

#### `codex.cmd mcp list` 中没有 `nexus-local`

重新执行接入命令，确认命令没有报错，然后完全退出并重新启动 Codex。

#### MCP 显示 enabled，但 Agent 看不到工具

当前 Codex 任务不会动态加载刚写入的 MCP 配置。新建任务或重启 Codex 后再试。

#### Agent 能列出终端，但读不到日志

先启动 Nexus Control，并在对应终端产生一次输出。日志由 Nexus 持续保存；正式安装版应保存在用户数据目录，源码版保存在项目的 `backend/logs` 目录。

#### Agent 无法发送命令

检查 `NEXUS_MCP_ALLOW_COMMANDS` 是否为 `1`，并确认当前调用包含 `confirm: true`。只读工具不需要这个设置。

## 终端类型

新建终端时可以选择：

- WSL Ubuntu：通过 WSL 和 tmux 运行，应用重启后可以重新接入原会话。
- Windows PowerShell：通过 Windows ConPTY 运行，不经过 Ubuntu。
- PowerShell 7：仅在本机安装 `pwsh` 后可选。
- CMD：通过 Windows ConPTY 运行。

PowerShell、PowerShell 7 和 CMD 会在切换页面或最小化时继续运行；删除终端或退出 Nexus 时结束。WSL 中由 tmux 托管的服务会话在 Nexus 退出后仍然保留。
